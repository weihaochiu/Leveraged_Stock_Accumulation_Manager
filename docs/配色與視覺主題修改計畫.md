## 1. 問題說明

目前主畫面在 Windows 深色系統主題下，出現嚴重的可讀性問題：

1. 工具列為白色背景，但按鈕文字繼承系統的白色前景色，導致功能名稱幾乎消失。
2. 篩選列標籤、下拉選單與輸入框的文字對比不足。
3. KPI 資訊列使用淡藍背景，但文字仍為白色，資訊無法閱讀。
4. 表格表頭為淺灰藍背景，表頭文字卻為白色，欄位名稱不清楚。
5. 按鈕、下拉選單及表格右側角落混入 Windows 深色樣式，造成黑色區塊與突兀陰影。
6. 部分對話框以元件內嵌 StyleSheet 個別指定顏色，缺乏統一管理，未來修改容易遺漏。

根本原因不是單一色碼錯誤，而是目前 QSS 只指定部分背景色，沒有完整指定對應的文字色、邊框色、互動狀態與停用狀態。Qt 因此會從 Windows 系統主題繼承剩餘顏色，造成淺色背景與深色系統前景互相衝突。

## 2. 修改目標

1. 第一階段固定使用完整、可預期的淺色主題，不受 Windows 淺色／深色模式影響。
2. 所有主要文字與背景至少符合 WCAG AA 一般文字 4.5:1 的對比原則。
3. 以中性灰為主、藍色為操作主色，避免整個畫面過度鮮豔。
4. 顏色只負責輔助資訊，不讓使用者只能靠顏色判斷狀態。
5. 保留臺股顯示慣例：正報酬／上漲使用紅色，負報酬／下跌使用綠色。
6. 建立集中式主題模組，移除散落在各 Python 檔案中的硬編碼顏色。
7. 為未來增加深色模式保留架構，但本次不直接加入深色模式切換，以免同時擴大測試範圍。

## 4. 各區域修改計畫

### 4.1 主視窗與工具列

- 工具列固定使用白色背景、深色文字及淡灰下邊框。
- 所有工具列按鈕加入正常、滑入、按下、選取及停用狀態。
- 主要操作「新增買入」採藍色主按鈕；其他功能使用白底描邊的次要按鈕。
- 「新增賣出」屬於交易操作，但不使用整顆紅色按鈕，避免與刪除／錯誤語意混淆。
- 工具列分隔線固定為 `#CBD5E1`，避免繼承系統黑色。
- 下拉選單箭頭、功能選單與選單項目明確指定白底深色字及選取色。

### 4.2 搜尋與篩選列

- 搜尋框、ComboBox、日期與數值輸入元件統一為白底、深色字、灰色邊框。
- Placeholder 使用 `#64748B`，避免過淡。
- Hover 邊框改為 `#94A3B8`；Focus 邊框改為 `#2563EB`。
- 欄位名稱使用 `#334155`，不得再從系統主題繼承白字。
- 停用元件使用灰底與深灰字，仍須看得見停用前的值。

### 4.3 KPI 資訊列

- 整體背景保留淡藍 `#EFF6FF`，邊框使用 `#BFDBFE`。
- 一般說明文字使用 `#1E3A8A`；主要數字使用 `#0F172A` 並加粗。
- KPI 之間增加適當間距或分隔，不使用整行白色文字。
- 零值維持中性色，不用紅綠色造成「0 是異常」的暗示。
- 若日後改成獨立 KPI 卡片，沿用相同語意色，不另建一套色彩。

### 4.4 Master Table

- 表頭背景使用 `#E2E8F0`，文字使用 `#1E293B`，排序箭頭必須可見。
- 表格內容為白底深色字，交錯列使用 `#F8FAFC`。
- 選取列使用 `#DBEAFE` 背景與 `#0F172A` 文字，確保選取後數值仍清楚。
- Focus/current cell 邊框使用主藍色，不能出現黑色實心區塊。
- 表格空白區、右下角 corner button、捲軸與捲軸角落都明確指定淺色樣式。
- 正報酬用深紅字、負報酬用深綠字，避免使用過亮的純紅／純綠。
- 策略狀態採「淺色背景＋深色文字」：

  - 達到目標：淡紅背景＋深紅文字。
  - 接近目標：淡黃背景＋深褐文字。
  - 已回本持股：淡綠背景＋深綠文字。
  - 容許差額完成：淡藍背景＋深藍文字。

### 4.5 按鈕與互動狀態

- 一般按鈕：白底、深色字、灰色邊框。
- 主要按鈕：藍底白字，只用於每個畫面最主要的確認操作。
- 危險按鈕：紅底白字，只用於刪除或不可逆操作。
- Hover：背景略微加深；Pressed：再加深一階；Disabled：灰底灰字。
- 鍵盤焦點須有清楚的藍色外框，不能只依靠滑鼠 Hover。
- 移除 Windows 原生黑色立體陰影，統一改為扁平化邊框。

### 4.6 對話框、分頁與訊息框

- 所有新增／編輯表單沿用同一套文字、輸入框、按鈕與背景色。
- `QTabWidget`、`QGroupBox`、`QMenu`、`QMessageBox`、`QInputDialog`、`QFileDialog` 均納入主題，不只處理主畫面。
- 表單驗證錯誤使用淡紅背景、深紅文字與明確錯誤訊息。
- 說明文字集中使用次要文字色，不再由每個 Dialog 自行硬編碼。
- 系統原生檔案選擇視窗若無法完全套用 QSS，至少確保程式自有對話框一致。

### 4.7 狀態列與備份狀態

- 狀態列使用白底、上邊框與深灰文字。
- 備份成功、部分成功、失敗除了顏色，也顯示完整繁體中文狀態。
- 資料庫路徑等次要資訊使用 `#475569`，不可淡到無法閱讀。

### 4.8 分析圖表

- 圖表背景與卡片背景統一為白色，座標軸及標籤使用深灰色。
- 圖表色彩依資料語意選擇，不用同一個紅綠色同時代表不同意思。
- 每張圖保留標題、圖例與數值標籤，避免只用顏色區分系列。
- 圖表輸出圖片也須使用同一配色，避免 GUI 正常但匯出圖仍看不清楚。

## 5. 程式架構調整

### 5.1 新增集中式主題模組

建議新增：

```text
stock_manager/
└─ ui/
   ├─ __init__.py
   ├─ theme.py          # 色彩常數、QPalette 與 QSS 產生器
   └─ styles.qss        # 集中管理所有元件樣式
```

`theme.py` 負責：

1. 定義具語意的色彩名稱，例如 `COLOR_TEXT_PRIMARY`、`COLOR_SUCCESS_BG`。
2. 在啟動時建立完整 `QPalette`，先阻止 Windows 深色前景色滲入。
3. 載入單一 `styles.qss` 套用至整個 `QApplication`。
4. 提供表格正負報酬與策略狀態的顏色對照函式。

### 5.2 移除分散的硬編碼 StyleSheet

需整理的既有位置至少包括：

- `stock_manager/main.py`
- `stock_manager/app/main_window.py`
- `stock_manager/dialogs/analysis_dialog.py`
- `stock_manager/dialogs/ocr_dialog.py`
- `stock_manager/dialogs/recovery_dialog.py`
- `stock_manager/dialogs/data_dialogs.py`

元件若有特殊用途，應使用 `objectName` 或動態 property，例如：

```python
button.setProperty("role", "primary")
label.setProperty("status", "success")
```

QSS 再依 property 套用樣式，避免在 Python 內重複寫色碼。

## 6. 實作順序

1. 建立色彩常數、完整 `QPalette` 與集中式 QSS。
2. 修正主視窗、工具列、搜尋篩選列、KPI 與 Master Table。
3. 修正按鈕的 Hover、Pressed、Focus、Disabled 等互動狀態。
4. 修正各資料輸入、分析、OCR、回本模擬、設定與備份對話框。
5. 統一策略狀態、備份狀態、正負報酬的語意色。
6. 檢查圖表畫面及圖檔匯出配色。
7. 在 Windows 淺色／深色模式下分別啟動程式並執行視覺驗收。
8. 完成後再封裝新版 ZIP，預計版本號提升為 v1.0.2。

## 7. 驗收標準

### 7.1 必須通過

- Windows 設為深色模式時，工具列、KPI、表頭、輸入框及狀態列均能清楚閱讀。
- Windows 設為淺色模式時，畫面配色與深色模式下的程式淺色主題一致。
- 所有按鈕在正常、Hover、Pressed、Focus、Disabled 狀態下皆可辨識。
- 表格排序箭頭、捲軸、右下角角落元件不再出現突兀黑塊。
- 選取表格列後，所有欄位文字仍清楚可讀。
- 所有繁體中文標籤、提示、對話框與選單文字不再出現白底白字。
- 正負報酬符合臺股紅漲綠跌慣例。
- 狀態不只依賴顏色，必須同時保留文字。
- 既有功能、自動測試、Excel、備份與資料庫行為不因換色而改變。

### 7.2 建議測試環境

- Windows 10／11：系統淺色模式。
- Windows 10／11：系統深色模式。
- 顯示縮放：100%、125%、150%。
- 空資料庫、少量資料及大量資料三種表格狀態。
- 一般顯示器與高 DPI 顯示器。

## 9. 預期結果

完成修改後，程式會呈現乾淨、穩定的淺色金融管理介面。工具列、KPI、篩選器與 Master Table 在 Windows 任一系統主題下都具有一致的深色文字與足夠對比；紅綠色只用於具有明確金融語意的狀態，其他操作以藍色與中性灰為主，降低視覺負擔並提升長時間使用的可讀性。
